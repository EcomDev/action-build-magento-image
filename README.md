# Build Magento Data Container Image

A composite GitHub Action that builds (and optionally pushes and attests) multi-architecture Docker container images (`mariadb`, `mysql`, `opensearch`, and `media`) from pre-built Magento data artifacts generated by [`ecomdev/action-build-magento-data-artifact`](https://github.com/EcomDev/action-build-magento-data-artifact).

The resulting images contain pre-initialized database files, OpenSearch indices, or Magento media assets so containers start ready to use in [Testcontainers](https://testcontainers.com/), CI/CD integration pipelines, and local development environments without slow SQL imports or reindexing at startup.

## Overview

During execution, this action:

1. Downloads the specified GitHub Actions workflow artifact (`artifact`) into `./artifact/` via [`actions/download-artifact@v8`](https://github.com/actions/download-artifact).
2. Unpacks the archived Magento data inside `./artifact/`:
   - `search.tgz` → `./artifact/search/`
   - `media.tgz` → `./artifact/media/`
   - `db.sql.gz` → `./artifact/db.sql`
3. Sets up QEMU ([`docker/setup-qemu-action@v4`](https://github.com/docker/setup-qemu-action)) and Docker Buildx ([`docker/setup-buildx-action@v4`](https://github.com/docker/setup-buildx-action)) for multi-platform image builds.
4. Logs into the target container registry (`registry`, default `ghcr.io`) via [`docker/login-action@v4`](https://github.com/docker/login-action) when `push` is enabled.
5. Extracts OCI image tags and labels via [`docker/metadata-action@v5`](https://github.com/docker/metadata-action).
6. Builds (and optionally pushes) the container image via [`docker/build-push-action@v7`](https://github.com/docker/build-push-action) using `Dockerfile-<containerType>`, GitHub Actions cache (`type=gha,mode=max`), and build argument `SOURCE_VERSION=<version>`.
7. Generates and pushes a build provenance attestation to the registry via [`actions/attest@v4`](https://github.com/actions/attest) when `push` is enabled.

## Supported Container Types

The `containerType` input selects which Dockerfile is built from the unpacked artifact data:

| `containerType` | Base Image | Embedded Data | Notes |
| --- | --- | --- | --- |
| `mariadb` | `wardenenv/mariadb:<version>` | `/var/lib/mysql` | Multi-stage build using `ghcr.io/wardenenv/mariadb:<version>` to import `*.sql` at build time (`MYSQL_INIT_ONLY=1`) and copy the initialized data directory into the final image. |
| `mysql` | `wardenenv/mysql:<version>` | `/var/lib/mysql` | Multi-stage build using `ghcr.io/wardenenv/mysql:<version>` to import `*.sql` at build time (`MYSQL_INIT_ONLY=1`) and copy the initialized data directory into the final image. |
| `opensearch` | `ghcr.io/wardenenv/opensearch:<version>` | `/usr/share/opensearch/data` | Replaces the OpenSearch data directory with the pre-indexed `search/` directory (`opensearch:opensearch`). |
| `media` | `scratch` | `/` | Minimal data-only image containing unpacked `media/` files with ownership `1000:1000` and permissions `0777`. `version` is unused at runtime (pass `'none'`). |

### Pre-Configured Database Credentials (`mariadb` and `mysql`)

Both database container images come pre-configured with the following default environment variables:

| Environment Variable | Value |
| --- | --- |
| `MYSQL_DATABASE` | `magento` |
| `MYSQL_USER` | `magento` |
| `MYSQL_PASSWORD` | `magento` |
| `MYSQL_ROOT_PASSWORD` | `magento` |

## Expected Data Artifact Contents

The workflow artifact referenced by `artifact` must contain all three archives produced by [`ecomdev/action-build-magento-data-artifact`](https://github.com/EcomDev/action-build-magento-data-artifact) (all three are extracted before Docker Buildx runs):

| File | Description |
| --- | --- |
| `db.sql.gz` | Gzip-compressed SQL dump of the installed `magento` database. |
| `media.tgz` | Tarball (`tar -czf`) of Magento's `pub/media` directory (`media/`). |
| `search.tgz` | Tarball (`tar -czf`) of OpenSearch data (`search/`). |

## Usage

### Basic Example (Build and Push to GHCR)

```yaml
name: Build Magento Container Images

on:
  workflow_dispatch:
  push:
    branches: [main]

permissions:
  contents: read
  packages: write
  id-token: write
  attestations: write

jobs:
  build-artifact:
    runs-on: ubuntu-latest
    steps:
      - name: Build Magento 2.4.8 Data Artifact
        uses: ecomdev/action-build-magento-data-artifact@v1.4.0
        with:
          name: magento-2.4.8
          magento-version: '2.4.8-p5'
          php-version: '8.3'
          mariadb-version: '11.4'
          opensearch-version: '3.0'

  build-mariadb-image:
    runs-on: ubuntu-latest
    needs: build-artifact
    steps:
      - name: Build and Push MariaDB Data Image
        uses: ecomdev/action-build-magento-image@v1.0.0
        with:
          artifact: magento-2.4.8
          containerType: mariadb
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}
          imageName: ${{ github.repository }}/mariadb
          imageTags: type=raw,value=2.4.8
          version: '11.4'
          push: 'true'
```

### End-to-End Matrix Pipeline

Combine [`ecomdev/action-build-magento-matrix`](https://github.com/EcomDev/action-build-magento-matrix), [`ecomdev/action-build-magento-data-artifact`](https://github.com/EcomDev/action-build-magento-data-artifact), and `ecomdev/action-build-magento-image` to automatically build all supported Magento releases and all four container types (`mysql`, `mariadb`, `opensearch`, and `media`):

```yaml
name: Build Magento Data Images

on:
  pull_request:
  push:
    branches: [main]

permissions:
  contents: read

jobs:
  generate-matrix:
    runs-on: ubuntu-latest
    outputs:
      builds: ${{ steps.matrix.outputs.builds }}
      images: ${{ steps.matrix.outputs.images }}
    steps:
      - name: Generate Magento Version Matrix
        id: matrix
        uses: ecomdev/action-build-magento-matrix@v1.0.1
        with:
          months: '12'
          sample-data: 'true'

  build-magento:
    runs-on: ubuntu-latest
    needs: generate-matrix
    strategy:
      fail-fast: false
      matrix:
        include: ${{ fromJson(needs.generate-matrix.outputs.builds) }}
    steps:
      - name: Build Magento Data Artifact (${{ matrix.name }})
        uses: ecomdev/action-build-magento-data-artifact@v1.4.0
        with:
          name: ${{ matrix.name }}
          magento-version: ${{ matrix.magentoVersion }}
          stability: ${{ matrix.stability }}
          mariadb-version: ${{ matrix.mariaDbVersion }}
          opensearch-version: ${{ matrix.openSearchVersion }}
          php-version: ${{ matrix.phpVersion }}
          sample-data: ${{ case(matrix.sampleData, 'true', 'false') }}
          token: ${{ github.token }}

  build-container:
    runs-on: ubuntu-latest
    needs: [generate-matrix, build-magento]
    permissions:
      contents: read
      packages: write
      id-token: write
      attestations: write
    strategy:
      fail-fast: false
      matrix:
        include: ${{ fromJson(needs.generate-matrix.outputs.images) }}
    steps:
      - name: Build ${{ matrix.containerType }} Image (${{ matrix.artifact }})
        uses: ecomdev/action-build-magento-image@v1.0.0
        with:
          artifact: ${{ matrix.artifact }}
          containerType: ${{ matrix.containerType }}
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}
          imageName: ${{ github.repository }}/${{ matrix.containerType }}
          imageTags: ${{ matrix.tag }}
          version: ${{ matrix.version }}
          push: ${{ github.event_name != 'pull_request' }}
          platforms: linux/amd64,linux/arm64
```

## Inputs

| Input | Required | Default | Description |
| --- | :---: | --- | --- |
| `artifact` | **Yes** | — | Name of the GitHub Actions workflow artifact to download and build the image from. |
| `containerType` | **Yes** | — | Target container image type to build: `mariadb`, `mysql`, `opensearch`, or `media`. |
| `imageName` | **Yes** | — | Image repository path without the registry hostname (combined as `<registry>/<imageName>`, e.g., `my-org/magento-data/mariadb`). |
| `imageTags` | **Yes** | — | Tag definitions passed to `docker/metadata-action` `tags` input (e.g., `type=raw,value=2.4.8` or newline-separated tag rules). |
| `version` | **Yes** | — | Upstream Warden base image tag passed as the `SOURCE_VERSION` Docker build argument (e.g., `'11.4'`, `'8.4'`, `'3.0'`, or `'none'` for `media`). |
| `registry` | No | `ghcr.io` | Target container registry hostname. |
| `username` | No | `''` | Container registry username used when `push` is not `'false'` (e.g., `${{ github.actor }}` for GHCR). |
| `password` | No | `''` | Token/password passed as `github-token` to `actions/download-artifact` and used as the container registry password when `push` is not `'false'` (e.g., `${{ secrets.GITHUB_TOKEN }}`). |
| `push` | No | `'false'` | Push built images and provenance attestations to `registry` when set to any value other than `'false'` (e.g., `'true'`). |
| `platforms` | No | `linux/amd64,linux/arm64` | Comma-separated list of target OCI platforms for Docker Buildx. |

## Permissions

Configure job or workflow `permissions` according to whether images are pushed:

| Mode | Required Permissions | Purpose |
| --- | --- | --- |
| Build only (`push: 'false'`) | `contents: read`<br>`packages: read` | Pull base images from `ghcr.io` and download workflow artifacts. |
| Build, push & attest (`push: 'true'`) | `contents: read`<br>`packages: write`<br>`id-token: write`<br>`attestations: write` | Push images to GHCR and sign/upload Sigstore OIDC build provenance attestations via `actions/attest`. |

> **Note on external registries:** Because `password` is forwarded to `actions/download-artifact` (`github-token`) as well as `docker/login-action`, use a valid GitHub token (such as `${{ secrets.GITHUB_TOKEN }}`) when publishing to `ghcr.io`.

## Requirements

- **Runner Environment**: Linux GitHub Actions runner (such as `ubuntu-latest`) with Docker, `tar`, and `gunzip` available.
- **Workflow Artifact**: An uploaded artifact in the same workflow run matching `artifact` and containing `db.sql.gz`, `media.tgz`, and `search.tgz`.
